## Server integration API (same semantics through web/PRISMA)
Public trusted PHP entry: brainwash_dispatch(string $operation, array $payload, array $context = []): array, in server/runtime.php. This factory owns loading the CHIM source/runtime helpers, shared playthrough lease, connection and authoritative scope. It must revalidate a supplied Department context scopeKey when present. Other context fields are not client authority. Source readiness: brainwash_runtime_ready(): bool. Namespace functions prefixed brainwash_. Runtime errors: BrainwashFault with public readonly string $wireCode in [invalid_request,not_found,stale_revision,stale_context,conflict,unavailable,forbidden]. Handler maps to fixed public messages; no secrets/prompts in errors.

Editable native fields (and only these): core,npc_static_bio,personality,appearance,occupation,skills,speechstyle,goals. No identity/voice/refid/profile/relationships writes. Each string ≤8192 UTF-8 bytes; combined native card text ≤20000 bytes for transport. Oversized existing card refuses with explicit error, never silently truncates then overwrites. Optional beliefs is one bounded text string ≤4000 bytes, separately stored in plugin_extended_data.brainwash and labeled fiction/belief in prompts, never copied to npc_static_bio.

Operations:
- brainwash.catalog.read payload {} -> {actors:[{actorKey:'npc:<positive integer>',label:string}],limited:bool}, max64 NPCs.
- brainwash.card.read {actorKey} -> {actorKey,label,scope:string,revision:64hex,fields:{all eight string fields},beliefs:string,draftId:uuid|null,lastOperation:{operationId:uuid,state:'applied'|'undone'}|null}. No entire history/draft in this response.
- brainwash.draft {actorKey,expectedRevision:64hex,operationId:uuid,mode:'manual'|'ai',changes:object of 0..8 allowed fields,instruction:string≤2000 UTF-8 bytes,beliefs?:string} -> {actorKey,scope,revision,draftId:uuid,origin:'manual'|'ai',before:object of selected field strings,changes:object of selected field strings,beliefsBefore?:string,beliefs?:string}. At least one selected field or beliefs required; only selected fields may be generated/changed. Manual mode needs no model. AI mode calls configured CHIM Profile Tasks connector once with current card, selected fields, author instruction; strict bounded JSON parsing rejects wrong types/extra/unselected fields. No factual event-review capability is claimed in v1. Model output is draft only. No core field changes or history record at draft. Store one current draft per NPC namespace; recheck scope/revision after model call, before saving draft, and never hold row lock during network I/O.
- brainwash.apply {actorKey,draftId:uuid,operationId:uuid,acceptedFields:[allowed field names],acceptBeliefs:bool} -> {operationId,state:'applied',card:<card.read>}. At least one actual selected change. Verify draft ID and original revision under row lock plus current timeline fence; never apply user-invented fields or a field absent in the saved draft. Snapshot + selected field edits + plugin namespace receipt + removal of current draft commit in ONE transaction on ONE connection. Preserve other plugin namespaces and all unrelated NPC columns. Repeated same operationId/payload returns same confirmed state without another write; reused ID with other payload fails conflict. A superseded/stale draft fails safely.
- brainwash.undo {actorKey,operationId:uuid,appliedOperationId:uuid} -> {operationId,state:'undone',card:<card.read>}. Only last accepted Brainwash operation is undoable. Check same timeline and that touched fields/beliefs still equal applied values. Restore touched values only, preserve unrelated later edits and other plugin data. Atomic history/state/receipt; duplicate undo idempotent. Never restore entire NPC row. Refuse overlapping edits and unknown/old operation IDs.

Readback after uncertain apply/undo is card.read.lastOperation. UI locks mutations after uncertain transport failure until explicit readback resolves it; do not auto retry. A new current draft may supersede the previous draft, but must never make an old draft applyable again. Bound stored draft/last receipt; do not grow a journal forever in the NPC namespace. Core restore generation and active playthrough ID form scope: same-ID restore must invalidate drafts and old operation replay, not just playthrough switches. Acquire existing shared work.lock, check pause and core generation without inventing a different restore policy. Reuse inspected core read helpers where possible; do not invoke automatic backups/migrations simply to read state. Missing/ambiguous scope fails closed. Core source compatibility pin required for direct transactional SQL. For synthetic PostgreSQL tests, service accepts an owned test connection and explicit test scope; HTTP clients cannot choose DB/scope.

## Shared editor module
Canonical assets server/assets/editor.js and editor.css in Brainwash. No new dependency.
Script exposes window.BrainwashEditor.mount(rootElement, {request: async(operation,payload)=>data}) -> {reset(), setAvailable(bool)}. May export CommonJS for Node tests. Same component is used by web page and copied into Department ui/brainwash-editor.js + .css by coordinator. It supplies NPC selection, all eight field textareas with individual selection checkboxes, beliefs edit checkbox/text, instruction and manual/AI draft actions, before/after review, explicit apply accepted fields/beliefs, narrow undo and refresh/reconciliation. Use textContent/value (never injected HTML for NPC/model text), accessible labels and status. reset clears card/draft/selection after scope/auth/native invalidation. Pending stale promises must not repaint a reset/new actor's state. No fields become applied merely by typing or clicking draft. Review shows before and after; accepted fields can be deselected. Expected revision always comes from last server read, not locally computed card hashes.

## Web authentication
Server page manifest config_url points to index.php; it is a real usable web page, not just an API. Use server-side configured secret hash or existing verified core authorization; never assume config_url or CORS is auth. Prefer one local passphrase login with password_hash/password_verify, server-private config outside webroot, session-bound CSRF tokens for mutation, strict same-origin and bounded JSON. No default password, no tokens in URLs/localStorage/logs. Test real browser cookies/POST and cross-origin rejection. Passphrase can be provisioned only in TEST2 private file; do not print it. Both manual and AI operations use same server service as Department. AI remains opt-in and unavailable when configured Profile Tasks disabled/unavailable. Prompt contribution excludes another NPC and disappears when plugin/belief disabled.
